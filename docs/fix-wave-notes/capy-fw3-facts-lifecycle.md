## Facts and takes lifecycle: stable fact ids, lossless fences, lossless merges

- **Editing a page no longer changes its fact ids (write-path audit B-5).** The legacy `extract_facts` reconcile (every brain until managed persistence is activated) keys fence rows by row number, the fence's own unique identity. A row whose number and claim are still in the fence keeps its id and has its other cells (notability, visibility, context, dates, confidence, typed claim) updated in place, so an id handed out by `recall` keeps working for `forget`, and `source_session`, `created_at`, consolidation state and vectors survive the edit. A row whose number leaves the fence, or whose claim is rewritten, is expired and detached (`row_num` NULL), never deleted, the same rule the managed projection applies. Until a new row can be embedded, rows with vectors keep their positions and the new row waits (restrictions still apply). `ExtractFactsResult` gains `factsUpdated`; `factsDeleted` now counts rows expired out of the fence.
- **A claim that reverts stays active (B-4).** NYC → SF → NYC used to fold the current row onto the struck history row with the same text and leave the entity with no active value. Only duplicate active rows with the same claim and source collapse now.
- **Supersession chains keep every link (B-13).** A → B → C resolves `superseded_by` on both hops; a forgotten target or a cycle still resolves to NULL with a warning. Both engines' `insertFacts` and the reconcile share the resolver.
- **Facts of a deleted page leave recall (B-7).** Each `extract_facts` run expires (without detaching) the active fence-owned facts of soft-deleted pages in its source; restoring the page re-activates the same rows on its next reconcile, and forgotten claims stay expired.
- **Fence dates round-trip (B-6, B-20).** `valid_from` and `valid_until` cells keep `YYYY-MM-DD` for a UTC-midnight value and otherwise store a UTC timestamp to the second. A `remember(ttl: "1h")` fact is no longer expired by a rebuild or reimport, and a fact written in the evening west of UTC is no longer stamped with tomorrow's date. Applies to the fence writer, `remember` and managed `extract_facts`.
- **Fence numbers parse strictly (B-15).** `claim_value` accepts plain and scientific numbers, `1,234,567` separators, a leading currency symbol and a k/M/B suffix that scales (`2.5M` is 2,500,000, so a 2.5M → 900k ARR drop reads as a decline). `1,5`, `0.9abc` and other shapes are `FACTS_TABLE_MALFORMED`, which keeps the page's existing index, as does a non-numeric confidence.
- **Extractor confidence (B-16).** A numeric-string confidence (`"0.3"`) is read as stated instead of becoming 1.0. A missing or null confidence keeps the legacy 1.0 by default; `gbrain config set facts.extraction_missing_confidence 0.5` opts into a less certain value (opt-in because confidence feeds hot-memory ordering and decay and no matched eval has measured a new default). Unknown kinds are counted in a warning; remapping them from `fact` to `belief` is deferred, since it changes decay half-life and `fact` is the prompt's designed catch-all.
- **Fuzzy fact attribution only lands on entities (B-8 residue after #5668).** A same-name fuzzy candidate must be an entity page (person, company, fund, org, host, project, concept or deal, never a meeting or note) and the only such candidate.
- **Phantom-redirect merges are lossless (B-12).** The canonical fence lands in the page's file of record through the shared write-target resolver; the phantom's links move to the canonical page; the phantom slug is recorded in `slug_aliases`; every phantom fact moves by id (expired and superseded history included, never hard-deleted) and takes exactly the row number written to disk, with `superseded by #N` renumbered, so the canonical's next reconcile keeps ids and vectors; a fuzzy canonical needs a clear margin and must agree with the single prefix candidate.
- **Takes bootstrap from pages (B-14).** Claims the page's takes fence already holds are not appended again (reruns with `--include-covered` or hand-added takes no longer duplicate gradeable takes), each run stops at a USD budget (`takes.bootstrap_budget_usd`, default 5.0, 0 disables), and a failed model call is a skipped page with an `llm_error:<code>` reason instead of looking like "nothing to extract".
- **Fence takes extraction (B-18).** The v0_28_0 / fs / db extraction resolves pages within their source and never onto deleted pages, re-extracts a slug in every source that holds it (no hard-coded `default`), and removes takes whose rows left a cleanly parsed fence.
- **Temporal supersession direction (B-17).** Contradiction resolutions order dates by instant (timezone-bearing dates included); same-day or unparseable dates produce the "date order unclear" note instead of a supersede command that picks an arbitrary side.
- **Entity identity links (B-19).** The canonical demotion and the link run in one transaction, and re-linking the canonical member to update its confidence no longer demotes it; `canonical: false` still demotes explicitly.
- **Write-path failures are visible (B-21).** Resolver database errors propagate instead of becoming a fallback slug (a missing pg_trgm still degrades the fuzzy arm); the fence writer's file-only row-number fallback logs `FACTS_ROW_NUM_HINT_UNAVAILABLE`; a failed page-cache mirror logs `FACTS_PAGE_MIRROR_FAILED`; supersede bookkeeping failures log `FACTS_SUPERSEDE_BOOKKEEPING_FAILED`. The loops-extract fact-projection catch is covered by open #5586 (@andreineacsu). A doctor-surfaced counter for these codes is deferred.

Builds on the write-path fixes in #5666 and #5668 (@garrytan).
