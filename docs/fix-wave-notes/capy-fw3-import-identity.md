## Import identity and slug renames (branch `capy/fw3-import-identity`)

- **Importing another directory can no longer rename a live page that reuses a frontmatter id (#5675).** Move inference is now tied to the root the existing page was imported from, never the incoming import's root. That root comes from the `file://` origin `importFromFile` now records in `pages.source_uri` (non-file provenance such as a capture URI is never replaced), or else from the source's configured `local_path` (the legacy `sync.repo_path` for the default source). A missing path under a different root no longer counts as evidence of a move. When the content differs, a move needs the old file gone under its own root, the new file under that same root, and the same file name or title. So a full sync where a new note reuses a deleted note's template id now creates a separate page, and the old page is retired normally. Same-root moves, with or without edits, and converging overlapping roots behave as before. Regression tests covering the reporter's repro and the full-sync variant are in `test/import-identity-move.test.ts`. Thanks to @Grimnoth for the precise report and repro.
- **Renames carry facts and search aliases (#5431 item 3).** `updateSlug` now moves `facts.entity_slug`, `facts.source_markdown_slug` and `page_aliases.slug` in the same transaction as the rename, on both engines. Leftover rows at the new slug from a purged page give way to the moved rows. Thanks to @clatyceo.
- **Transcript re-ingest keeps frontmatter it doesn't render (#5431 item 2).** Keys that another tool or the operator added to a conversation page (for example a review flag) now survive a re-render. Safety markers and the atom-scan marker are still recomputed from the new content. Thanks to @clatyceo.
- **The thin client honors long timeouts (#5100, remaining parts).** `callRemoteTool` now passes the caller's `timeoutMs` to the MCP SDK as the request deadline, so the SDK's independent 60-second default no longer cuts off slow calls. An SDK `RequestTimeout` is now reported as a timeout, not an unreachable server. A new regression test confirms that `put_page` commits before any embedding runs and queues the embedding durably (that persistence-first behavior already shipped in v0.50.2.0). Contributed by @xaviroblessarries.
