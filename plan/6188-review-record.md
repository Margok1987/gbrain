# Plan: malformed facts/takes fences never block a sync and repair themselves (#6188)

Thread: GBRA-54. Repo: garrytan/gbrain. Base: master (v0.60.95.0 at planning time; fix wave 10 is next in the merge train as v0.60.96.0 and touches the fence parsers).

## Implementation plan

### Problem (verified in code, 2026-10-06)

- `compileCanonicalProjections` (`src/core/persistence/canonical-projections.ts:228`) throws `invalid_params` "A canonical facts or takes fence cannot be parsed losslessly." when either fence parser returns any warning. Every coordinated writer calls it through `prepareCanonicalProjections`: managed sync (`sync-prepare.ts:427`), put_page (`page-prepare.ts:403`), file import (`import-prepare.ts:196`), reconcile, connector sync, file repair, synthesize, company brain.
- The managed sync screen (`screenFrozenImport` in `sync-screen.ts`, via `screenSyncImport` → `screenImportContent`) checks size, frontmatter, slug conflicts and the sanity gate, never fences. So a malformed fence passes the screen, is admitted as a request, fails in preparation, and the cursor goes `blocked`.
- The #5988 in-place conversion (`convertBlockedCursor`, `sync-run.ts:377`) only converts failures `isContentRefusal()` recognizes. `invalid_params` is not one, so `--retry-failed` reproduces the block until a person edits the file. No hold is written, so `gbrain sources status` shows nothing.
- `importFromContent` already rewrites fence content before projection for other reasons (`mergeHiddenFactRowsIntoBody`, `preserveWithdrawnFenceRows`, `import-file.ts:571-577`), and managed sync already writes canonical corrections back into the file (`overlay`/`writeback`, `sync-prepare.ts:418-434`, committed through the Git target effect). Both are the hooks this plan reuses.
- Parser warning classes (`facts-fence.ts:197-335`, `takes-fence.ts:253-394`) map one-to-one onto the issue's failure table: `*_FENCE_UNBALANCED`, `*_TABLE_MALFORMED` (short rows, unknown kind/visibility/notability, invalid row_num, non-numeric confidence/weight, row before header, no header), `*_ROW_NUM_COLLISION`, `TAKES_HOLDER_INVALID`, `TAKES_FENCE_NEAR_MISS`.

### Goal

A malformed fence never blocks a sync. Most fences are fixed for free, inline, in the same write. What is left is held (the rest of the sync proceeds) and repaired automatically after the sync, by a resolver pass and then a frontier-LLM pass, under validation gates and a daily spend cap. A one-shot command clears the existing backlog, and doctor counts what's left.

### Design: three repair tiers, one validator

```
 file / put_page body
        │
        ▼
 ┌──────────────────────────────┐   pure, sync, free, deterministic
 │ Tier 1: normalizeFences()    │   (runs in the screen AND in importFromContent,
 │  + validateFenceRepair()     │    same function, same result)
 └──────────────┬───────────────┘
        clean? ─┴─ yes → import continues; managed sync writes the normalized
        │              file back (existing overlay/writeback) + receipt fixes
        no (residual warnings)
        ▼
 managed/legacy sync: hold `invalid_fence` (cursor advances, nothing blocks)
 put_page / remember / extractors: typed `invalid_fence` refusal naming row + warning + exact fix
        │
        ▼
 ┌──────────────────────────────┐   cycle phase `fence_repair` (after sync) and
 │ Tier 2: resolver pass        │   `gbrain repair fences --apply`
 │  holder display name →       │   (async, DB, free)
 │  existing people/ page       │
 ├──────────────────────────────┤
 │ Tier 3: frontier LLM pass    │   paid, capped, gated
 │  fence + schema only         │
 └──────────────┬───────────────┘
        validateFenceRepair() gates (a)-(e) on every tier's output
        pass → write back through managed_file_repair (managed) / file write + import
               (legacy) with receipt actor fence-repair; hold clears in that write
        fail → hold stays with the precise reason; still never blocks
```

### 1. `src/core/fence-repair.ts` (new, pure): normalizer + validator

`normalizeFences(section: string, ctx: { pageVisibility: 'private'|'world' }): { text: string; fixes: FenceFix[]; residual: FenceIssue[] }`, applied to `compiled_truth` and `timeline` separately, plus a page-level pass for cross-section row-number collisions.

Invariant 0 (blast radius): a section whose fences already parse with zero warnings is returned byte-identical. Only content that is refused today can change.

Tier-1 rules (each fix carries a class name used in receipts, holds and previews):

| Class | Rule |
|---|---|
| `close_fence` | Missing end marker: insert it after the last contiguous table row that follows the begin marker. Missing begin marker before a table that sits directly under an end marker is NOT guessed (residual). |
| `marker_form` | Two-dash near-miss markers (`<!-- gbrain:takes:begin -->`) → canonical three-dash form. |
| `renumber` | Row `0`, negative or non-numeric row number, and the second and later occurrence of a duplicate (within a fence and across the page's two sections) get the next free number (max + 1). The first valid occurrence of every number keeps it. |
| `pad_cells` | Rows missing trailing cells are padded. Required facts enums missing entirely get the existing write defaults: `confidence 1.0`, `notability medium`, `visibility private`. Takes missing `weight` → residual (no default exists). |
| `header_alias` | A non-canonical header whose columns all map to canonical columns (`holder`/`who`, `confidence`/`weight` for takes, `type`→`kind`, `date`→`since`, etc.) is rewritten into canonical column order and re-rendered through `renderFactsTable`/the takes renderer. Any unmappable column → residual. |
| `enum_synonym` | notability `critical`/`very_high`/`highest` → `high`, `very_low`/`minor` → `low`; visibility `internal`/`team`/`confidential`/`restricted`/`secret` → `private`, `public`/`shared` → `world` only when `effectiveVisibility(page)` is `world`, else `private`; case/whitespace variants of canonical values. |
| `kind_map` | Facts: a fixed synonym table (`proposal`/`suggestion`/`hypothesis` → `idea`, `opinion`/`view`/`insight`/`assessment`/`frame` → `belief`, `promise`/`pledge` → `commitment`, `meeting`/`launch`/`announcement`/`milestone` → `event`, everything else including `partnership`/`funding`/`investment`/`role`/`signal`/`claim`/`observation`/literal `[kind]` → `fact`), with `original kind: <word>` appended to the row's `context` (after any existing text, so `superseded by #N` / `forgotten:` parsing is unchanged). Takes: `assessment`/`recommendation`/`strategic position`/`opinion`/`view`/`belief` → `take`, `prediction`/`forecast` → `bet`, `guess`/`intuition` → `hunch`, otherwise `take`; takes have no context column, so the original word is kept in the receipt's fix list and in Git history. |
| `holder_alias` | `system`/`assistant`/`ai`/`agent`/`gbrain`/`model` → `brain`. Display names are left for Tier 2 (residual `holder_unresolved`). |
| `confidence_format` | `85%` → `0.85`; numeric confidence/weight strings with stray whitespace. Out-of-range numbers stay residual. |

`validateFenceRepair(before: string, after: string, ctx)` returns `{ ok: true } | { ok: false; gate: 'a'|'b'|'c'|'d'|'e'; detail }` and is the single gate every tier must pass before anything is written:

- (a) `after` parses with zero warnings under the strict parsers (and passes `compileCanonicalProjections`' marker and row-uniqueness checks).
- (b) The multiset of claim cells (strikethrough markers kept as written, whitespace collapsed) is identical before and after. Structure may change, content never.
- (c) Every row number that was valid and unique before still exists after and carries the same claim.
- (d) Visibility only tightens: a row that parsed as `private` before is never `world` after; an invalid/missing visibility may become `world` only through the `public`+world-page rule.
- (e) The row count is unchanged; the only allowed delta is header/separator lines.

Messages and hold records never carry claim text, holder names or cell values (same location-only rule #5988 uses): fence (facts/takes), section (body/timeline), row number, warning code, fix class.

### 2. Wire Tier 1 into every write path (inline, free)

- `screenImportContent` (`src/core/import-screen.ts`): after the frontmatter checks, run `normalizeFences` on the parsed body; non-empty residual → `refused` with new `ContentRefusal` code `invalid_fence` (location-only message). This one call covers the managed sync screen (`screenFrozenImport` and its dry run), legacy sync (`holdRefusedImport`), `importFromFile`, and `managed_file_repair`'s screen.
- `importFromContent` (`src/core/import-file.ts`, right after `preserveWithdrawnFenceRows`): apply the same normalizer to `parsed.compiled_truth` / `parsed.timeline`, so the stored page is normalized and its content hash covers the normalized body. Residual → return the typed `invalid_fence` refusal (as the screen path already does at `import-file.ts:330`). Result gains `fence_repairs: FenceFix[]`.
- Managed sync then sees `ready.parsedPage` differ from the parsed file → existing `overlay` → `writeback`: the normalized file is written with `expectedBeforeHash` and committed by the Git target effect. Read-only mirrors keep the fix in the database only (existing `mirror_read_only` path). Company-brain (immutable) sources keep refusing with `source_writeback_required` (they never rewrite repository files); that refusal is not a block, it is the existing company-source contract and is called out in docs.
- put_page / put_pages / remember / extractor and dream-phase writes go through `importFromContent`, so they normalize too and report `fence_repairs` (MCP result field + `[gbrain notice]` line telling the agent what changed and why). Residual → `invalid_fence` refusal whose `fix` names each row, the warning and the canonical vocabulary, so the writing agent fixes its own output (it is the cheapest model in the loop). No LLM call on the foreground write path.
- `compileCanonicalProjections` stays as the final backstop but throws the typed `invalid_fence` refusal (via `contentRefusalError`) instead of `invalid_params`, so anything that slips past the screen is still a recognized content refusal.
- `isContentRefusal` learns `invalid_fence` (in `CONTENT_REFUSAL_CODES`) plus a `LEGACY_CONTENT_MESSAGES` pattern for the old `invalid_params` "cannot be parsed losslessly" receipt. On upgrade, an already-blocked cursor (the issue's 40-hour stall) converts in place on its next run through the existing `convertBlockedCursor`: the normalizer fixes it and the entry is refrozen and imported, or the screen holds it and the cursor advances. No manual `--retry-failed` needed.
- `GitHoldCode` gains `invalid_fence`; `GitHoldMeta` gains `fence_version` (the normalizer's rule-set version). Discovery re-screens a held fence when the blob changes, when `sources retry-held` asks, or when `fence_version` is older than the running gbrain's (same mechanism as `recovery_version`). `gitHoldFix`/`gitHoldDocs` get an `invalid_fence` entry pointing at `gbrain repair fences --source <id>`.
- Fence holds count toward escalation like other content holds. Verify escalation only flags (`holds_escalated`) and never changes the outcome to `blocked`.

### 3. Tier 2 + Tier 3: the `fences` repair kind and the `fence_repair` cycle phase

New repair kind `fences` (`src/core/repair/fences.ts`, registered in `REPAIR_KINDS`/`registry.ts`), and new cycle phase `fence_repair` that runs it in auto mode right after `sync` (classified `writes` in `MANAGED_PHASE_TABLE`; added to the per-source freshness phases so it runs every autopilot tick).

Candidates per source: `invalid_fence` hold rows, plus database pages whose stored body has a fence that fails strict parsing (pages imported before the strict check), found with a keyset scan over pages whose `compiled_truth`/`timeline` contain a fence marker.

Per candidate:
1. Re-read the current bytes (file for holds, page snapshot for DB pages) and re-run Tier 1.
2. Tier 2: for each `holder_unresolved` row, `resolveEntitySlug` restricted to a hit on an existing live `people/` or `companies/` page (never the slugify fallback). A miss stays residual.
3. Tier 3, only if residual remains: send the fence block alone (never the rest of the page), the canonical schema, the residual warning codes and the page's visibility to the repair model, asking for the fence rewritten into canonical form with claims copied verbatim and unknown words kept in `context`. Model: `fences.repair.model`, default the configured chat model (`getChatModel()`, reasoning tier). Costs go through `BudgetTracker` with a per-page cap (`fences.repair.max_usd_per_page`, default $0.05) and a rolling UTC-day cap (`fences.repair.max_usd_per_day`, default $1.00), recorded like the existing daily caps (`autopilot.auto_drain.max_usd_per_day`). Unpriced model: warn and run under the default cap; under a user-set cap, refuse with the "look up the rate and register it" guidance (existing `pricingSetCommand`).
4. `validateFenceRepair(original, repaired)`. Fail → hold/candidate stays, with the failed gate and the tier recorded in the hold message (`invalid_fence: LLM repair rejected by gate (b), claim text changed`). LLM unavailable, budget spent, or `fences.repair.llm=false` → stays held with that precise reason. Nothing blocks.
5. Write back: managed sources through the existing `managed_file_repair` intent (exact bytes + import + hold clear + Git target effect in one coordinated write, bound to the file's before-hash and page revision); legacy sources write the file with a backup, import it, clear the hold, and print the commit step (the frontmatter repair's legacy path); DB-only pages through a revision-bound `put_page`. The receipt records `actor: fence-repair`, tier, fix classes, model (Tier 3), before/after sha256 and cost.

`gbrain repair fences [--source <id>] [--apply --expect <hash>] [--no-llm] [--max-usd <n>]`:
- Preview (default, read-only, no model call): lists every candidate page with its path/slug, warning codes, planned tier (`deterministic` / `resolver` / `llm`) and the estimated LLM cost from fence size, plus a total and the preview hash. Tier-1/2 previews show the exact diff; Tier-3 rows show "rewritten by <model> at apply time, gated by (a)-(e)".
- `--apply --expect <hash>`: applies exactly the previewed set (`changed_since_preview` for anything whose bytes or revision moved), tier by tier, under `--max-usd` (default the daily cap's remainder). Not explicit-only, so `doctor --remediate` can run it; not `consent: destructive`, because the cycle applies the same gated repairs automatically by default (taste decision surfaced at the gate).

Config (all default on, opt-out, per the upgrade-defaults-on rule): `fences.repair.enabled` (true), `fences.repair.llm` (true), `fences.repair.model`, `fences.repair.max_usd_per_page` (0.05), `fences.repair.max_usd_per_day` (1.00). `sync.holds=fail` keeps fail-closed behavior for people who want it (an invalid fence then blocks as today, with the new typed code).

### 4. Doctor check `fence_integrity`

Counts, per source, `invalid_fence` holds plus database pages whose fences fail strict parsing (same keyset scan, bounded batches, no file walk), split by planned tier. `ok` at 0; `warn` otherwise with the exact preview command (`gbrain repair fences --source <id>`) and `repairForCheck` wiring so `doctor --remediation-plan` lists the `fences` step. Explains when Tier 3 is off or over budget.

- Opening the takes kind set to schema-pack-declared kinds.
