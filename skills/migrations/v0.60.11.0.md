# Upgrade to v0.60.11.0: preview the recovery plan, then apply what the user agrees to

This release wires the `gbrain repair` kinds into doctor's remediation plan and
run, adds a preview-only recovery banner to `gbrain post-upgrade`, shows remote
callers one host-action line per recovery check, records which gbrain version
admitted and published each write, and adds an opt-in writer admin lock and an
operator autopilot pause. Schema migration v191 adds five nullable columns to
`persistence_requests` (`admitter_version`, `admitter_host_id`,
`consumer_version`, `consumer_host_id`, `published_at`) and records the
cutoff with the database clock. It deletes nothing and starts no service.

Never apply a repair, raise a limit, lock, unlock or resume on the user's
behalf without asking. Every step below that changes the brain needs the
user's agreement first.

1. **Upgrade hosts in order, with autopilot paused.** List with the user every
   host that uses this brain. On each host that runs connector jobs, pause
   autopilot first; upgrade the hosts that run the persistence consumer or own
   a worktree before the connector hosts; then resume:

   ```bash
   gbrain autopilot pause --reason "upgrading to v0.60.11.0"   # each connector host
   gbrain upgrade                                              # consumer and worktree-owner hosts first
   gbrain upgrade                                              # then connector hosts
   gbrain doctor --remediation-plan                            # step 3
   gbrain autopilot resume                                     # each host you paused
   gbrain sources status                                       # verify
   ```

   The pause survives `gbrain upgrade`. If schema work did not complete, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Relay the post-upgrade banner.** When `gbrain post-upgrade` prints an
   `[AGENT] Relay this to your operator` block, show it to the user as-is. It
   lists each finding and its count and never applies anything.

3. **Preview the recovery plan and ask.**

   ```bash
   gbrain doctor --remediation-plan
   ```

   Show the user the repair steps (each marked "requires user agreement"),
   their estimated cost, and the combined command at the end. Ask which to
   apply and what spending cap they accept.

4. **Apply only what the user agreed to**, with their cap:

   ```bash
   gbrain doctor --remediate --yes --include-repairs --max-usd <n>
   ```

   Pass `--no-embed` if they want no paid embeddings. If the run stops as
   budget-exhausted, ask again before running the printed resume command; the
   cap is cumulative across resumes.

5. **Report what is left.** The run prints each remaining finding with its
   class. For `operator_required`, relay the instruction (for example the
   #5413 quarantine commands in `docs/guides/repair.md#quarantine-self-captured-corpus-files`,
   or `gbrain upgrade` on a host that `writer_version` names). For
   `unsupported`, tell the user it is known and cannot be cleared yet.

6. **Verify.**

   ```bash
   gbrain doctor --remediation-plan         # no repair steps left
   gbrain sources writer status --json      # writer versions per host
   ```

Optional, only if the user asks: `gbrain sources writer lock` stops agents
from claiming, activating or transferring writers on this brain until the
operator runs `gbrain sources writer unlock`. See the writer admin lock in
`docs/architecture/topologies.md`.
# Upgrade to v0.60.11.0: managed connectors stop re-admitting unchanged pages

This release keys each managed Google and GitHub connector's checkpoint on its
parsed settings instead of the whole `sources.config` record, which the cycle
rewrote after every run. Connectors now resume where they stopped, skip
unchanged items without taking an admission, and treat writes the owner
accepted but has not published yet as progress. Managed import, working-tree
sync and company-profile sync skip unchanged items the same way.

One handler migration runs automatically: v176 copies each connector source's
newest committed checkpoint to its stable key, records a one-time re-walk for a
source whose newest checkpoint receipt was compacted, and removes checkpoint
rows no source can load. It deletes no page, receipt or write ID, holds no long
transaction and starts no background service. A rerun changes nothing.

1. **Upgrade in this order.** Mixed versions refuse with typed errors instead of
   losing data, but the order keeps refusals away. Copy and run:

   ```bash
   gbrain autopilot --status --json        # note whether autopilot runs connector jobs on this host
   gbrain upgrade                          # first: every host that runs the persistence consumer or owns a worktree
   gbrain upgrade                          # then: every host that runs connector jobs
   gbrain sources status --json            # verify (step 3)
   ```

   Pausing autopilot connector jobs during the upgrade is optional: a new
   connector talking to an old consumer fails `unsupported_mutation_protocol`,
   an old connector talking to a new consumer fails `connector_intent_outdated`,
   and in both cases the item is fetched again after the upgrade.

2. **Expect one admission spike, once.** Connector writes admitted before the
   upgrade used the retired intent format; each fails once with
   `connector_intent_outdated` (detail `pre_upgrade`, no action needed) and its
   item is fetched again on the next run under a new request ID. A source whose
   checkpoint had to be re-walked re-admits its window once. This first
   post-upgrade spike is expected and is not the #5470 churn.

3. **Verify with `gbrain sources status --json`.** Each connector source has a
   `connector` block ([shape](../../docs/guides/repair.md#connector-checkpoints)).
   After the second run, a quiet source shows `last_run.page_admissions: 0` and
   `skipped_unchanged` equal to its re-walked items.

4. **If a content setting changed since the resumed checkpoint, re-walk once.**
   For each source the migration printed
   `resumed from pre-upgrade checkpoint of <time>`, and `sources status` keeps
   that time as `resumed_from`. If you changed a content setting such as
   `g_history_days` since then, run
   `gbrain sync --source <id> --reset-checkpoint`. Unchanged pages are not
   admitted again.

5. **Account pinning.** Each connector source pins the account its credential
   resolves to on its first run (a migrated source on its first post-upgrade
   run). If a run refuses `connector_account_changed`, follow its two branches:
   restore the credential for the pinned account, or add a new source for the
   new account and archive the old one. No reset flag changes the account.

6. **Orphan checkpoint rows.** `gbrain doctor` reports `connector_checkpoints`
   when rows no source can load are older than 7 days. Preview with
   `gbrain repair connector-checkpoints`; apply with `--apply` after the user
   agrees.
# Upgrade to v0.60.11.0: managed maintenance writers, unbound sources, migration budgets

This release moves the remaining maintenance writers on managed brains onto
the persistence coordinator and keeps one refused cycle phase from stopping
the rest of maintenance. Schema migration v182 runs automatically and adds one
nullable column, `pages.database_only_reason`. It starts no background service
and calls no model provider.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.11.0 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Tell the user what changes on a managed brain.**
   - Global maintenance keeps running when one phase fails. The failed phase
     shows up in the cycle report with its error, and the run is reported as
     partial, not ok. A phase that failed after paying for model calls also
     appears in `gbrain doctor`'s `dream_paid_loop` check as
     `dream:phase:<phase>:<source>`; after fixing the cause, clear it with the
     `gbrain dream reset-key` command doctor prints.
   - Concept synthesis, chronicle extraction, the purge of deleted pages,
     enrichment, `add_link` / `remove_link`, bootstrap verify, the drift
     report, `grade_takes` and the facts writers now work on managed brains
     instead of refusing with `writer_coordinator_required`.
   - The lint phase on a managed brain reports issues but no longer rewrites
     canonical files.

3. **Postgres sources with a checkout folder but no owner.** Saving a page
   there still refuses by default, with `owner_unavailable` and detail
   `unbound_source`. The error names both fixes. Ask the user which one they
   want; do not pick for them:
   - bind the source: `gbrain sources writer status <source> --json`, then
     the printed `gbrain sources writer claim <source> --path <path>
     --admin-intent writer_claim --expected-state <admin_state>`; or
   - allow database-only saves:
     `gbrain config set persistence.unbound_write database_only`. Pages saved
     this way stay database-only after the source is bound.

   `gbrain doctor` reports the `unbound_source` count: ok while the source is
   unbound, a warning once it is bound.

4. **Embedding migrations print a worst-case authorization.** If
   `gbrain migrate embeddings --max-cost-usd <n>` stops with
   `embedding_budget_below_worst_case`, nothing was changed. Show the user
   the printed cap, worst case and command; rerun only with their agreement.
# Upgrade to v0.60.11.0: contextual mode for --no-embed pages, degenerate vectors refused

There is no schema migration in this part of the release, and nothing here
starts a background service. Two things may need one explicit pass on the
brain host, each after asking the user.

1. **Stamp the contextual retrieval mode on pages imported without one.**
   Pages imported with `--no-embed` (large syncs, connector sources) never
   recorded their mode, so later embed passes embedded them raw. When
   `gbrain doctor --json` shows `contextual_retrieval_coverage` with
   `details.mode_null_pages` above zero, preview the repair and show the user
   the counts and the embedding estimate:

   ```bash
   gbrain repair contextual-mode
   ```

   Apply only after the user agrees. Pages whose stored vectors already match
   are kept; a page whose embedding input changes is re-embedded once (paid
   embedding). Add `--no-embed` to stamp now and embed later with
   `gbrain embed --stale`.

   ```bash
   gbrain repair contextual-mode --apply
   ```

2. **After a PGLite crash repair, rebuild the vector indexes.** If the user saw
   "gbrain repaired this brain's PGLite WAL in place", run:

   ```bash
   gbrain reindex --vectors
   ```

   It rebuilds every HNSW index from the stored vectors; nothing is
   re-embedded and nothing is paid.

3. **Tell the user about one behavior change.** An embedding provider that
   returns an all-zero or broken vector for a chunk now gets that chunk
   refused with `embedding_zero_norm`; the page keeps its text and every other
   vector. The failure names `gbrain embed <slug>`; see
   `docs/guides/write-refusals.md`.
