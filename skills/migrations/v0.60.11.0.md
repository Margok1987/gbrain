# Upgrade to v0.60.11.0: managed connectors stop re-admitting unchanged pages

This release keys each managed Google and GitHub connector's checkpoint on its
parsed settings instead of the whole `sources.config` record, which the cycle
rewrote after every run. Connectors now resume where they stopped, skip
unchanged items without taking an admission, and treat writes the owner
accepted but has not published yet as progress. Managed import, working-tree
sync and company-profile sync skip unchanged items the same way.

One handler migration runs automatically: v176 copies each connector source's
newest committed checkpoint to its stable key, records a one-time re-walk for a
source whose newest checkpoint receipt was compacted, and removes checkpoint
rows no source can load. It deletes no page, receipt or write ID, holds no long
transaction and starts no background service. A rerun changes nothing.

1. **Upgrade in this order.** Mixed versions refuse with typed errors instead of
   losing data, but the order keeps refusals away. Copy and run:

   ```bash
   gbrain autopilot --status --json        # note whether autopilot runs connector jobs on this host
   gbrain upgrade                          # first: every host that runs the persistence consumer or owns a worktree
   gbrain upgrade                          # then: every host that runs connector jobs
   gbrain sources status --json            # verify (step 3)
   ```

   Pausing autopilot connector jobs during the upgrade is optional: a new
   connector talking to an old consumer fails `unsupported_mutation_protocol`,
   an old connector talking to a new consumer fails `connector_intent_outdated`,
   and in both cases the item is fetched again after the upgrade.

2. **Expect one admission spike, once.** Connector writes admitted before the
   upgrade used the retired intent format; each fails once with
   `connector_intent_outdated` (detail `pre_upgrade`, no action needed) and its
   item is fetched again on the next run under a new request ID. A source whose
   checkpoint had to be re-walked re-admits its window once. This first
   post-upgrade spike is expected and is not the #5470 churn.

3. **Verify with `gbrain sources status --json`.** Each connector source has a
   `connector` block ([shape](../../docs/guides/repair.md#connector-checkpoints)).
   After the second run, a quiet source shows `last_run.page_admissions: 0` and
   `skipped_unchanged` equal to its re-walked items.

4. **If a content setting changed since the resumed checkpoint, re-walk once.**
   For each source the migration printed
   `resumed from pre-upgrade checkpoint of <time>`, and `sources status` keeps
   that time as `resumed_from`. If you changed a content setting such as
   `g_history_days` since then, run
   `gbrain sync --source <id> --reset-checkpoint`. Unchanged pages are not
   admitted again.

5. **Account pinning.** Each connector source pins the account its credential
   resolves to on its first run (a migrated source on its first post-upgrade
   run). If a run refuses `connector_account_changed`, follow its two branches:
   restore the credential for the pinned account, or add a new source for the
   new account and archive the old one. No reset flag changes the account.

6. **Orphan checkpoint rows.** `gbrain doctor` reports `connector_checkpoints`
   when rows no source can load are older than 7 days. Preview with
   `gbrain repair connector-checkpoints`; apply with `--apply` after the user
   agrees.
