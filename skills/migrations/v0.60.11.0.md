# Upgrade to v0.60.11.0: managed maintenance writers, unbound sources, migration budgets

This release moves the remaining maintenance writers on managed brains onto
the persistence coordinator and keeps one refused cycle phase from stopping
the rest of maintenance. Schema migration v182 runs automatically and adds one
nullable column, `pages.database_only_reason`. It starts no background service
and calls no model provider.

1. **Confirm the upgrade finished on the brain host.**

   ```bash
   gbrain --version          # expect 0.60.11.0 or newer
   ```

   If `gbrain doctor` reports a partial migration, run
   `gbrain apply-migrations --yes --no-autopilot-install` on the brain host.

2. **Tell the user what changes on a managed brain.**
   - Global maintenance keeps running when one phase fails. The failed phase
     shows up in the cycle report with its error, and the run is reported as
     partial, not ok. A phase that failed after paying for model calls also
     appears in `gbrain doctor`'s `dream_paid_loop` check as
     `dream:phase:<phase>:<source>`; after fixing the cause, clear it with the
     `gbrain dream reset-key` command doctor prints.
   - Concept synthesis, chronicle extraction, the purge of deleted pages,
     enrichment, `add_link` / `remove_link`, bootstrap verify, the drift
     report, `grade_takes` and the facts writers now work on managed brains
     instead of refusing with `writer_coordinator_required`.
   - The lint phase on a managed brain reports issues but no longer rewrites
     canonical files.

3. **Postgres sources with a checkout folder but no owner.** Saving a page
   there still refuses by default, with `owner_unavailable` and detail
   `unbound_source`. The error names both fixes. Ask the user which one they
   want; do not pick for them:
   - bind the source: `gbrain sources writer status <source> --json`, then
     the printed `gbrain sources writer claim <source> --path <path>
     --admin-intent writer_claim --expected-state <admin_state>`; or
   - allow database-only saves:
     `gbrain config set persistence.unbound_write database_only`. Pages saved
     this way stay database-only after the source is bound.

   `gbrain doctor` reports the `unbound_source` count: ok while the source is
   unbound, a warning once it is bound.

4. **Embedding migrations print a worst-case authorization.** If
   `gbrain migrate embeddings --max-cost-usd <n>` stops with
   `embedding_budget_below_worst_case`, nothing was changed. Show the user
   the printed cap, worst case and command; rerun only with their agreement.
