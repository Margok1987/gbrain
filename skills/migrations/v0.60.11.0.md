# Upgrade to v0.60.11.0: contextual mode for --no-embed pages, degenerate vectors refused

There is no schema migration in this part of the release, and nothing here
starts a background service. Two things may need one explicit pass on the
brain host, each after asking the user.

1. **Stamp the contextual retrieval mode on pages imported without one.**
   Pages imported with `--no-embed` (large syncs, connector sources) never
   recorded their mode, so later embed passes embedded them raw. When
   `gbrain doctor --json` shows `contextual_retrieval_coverage` with
   `details.mode_null_pages` above zero, preview the repair and show the user
   the counts and the embedding estimate:

   ```bash
   gbrain repair contextual-mode
   ```

   Apply only after the user agrees. Pages whose stored vectors already match
   are kept; a page whose embedding input changes is re-embedded once (paid
   embedding). Add `--no-embed` to stamp now and embed later with
   `gbrain embed --stale`.

   ```bash
   gbrain repair contextual-mode --apply
   ```

2. **After a PGLite crash repair, rebuild the vector indexes.** If the user saw
   "gbrain repaired this brain's PGLite WAL in place", run:

   ```bash
   gbrain reindex --vectors
   ```

   It rebuilds every HNSW index from the stored vectors; nothing is
   re-embedded and nothing is paid.

3. **Tell the user about one behavior change.** An embedding provider that
   returns an all-zero or broken vector for a chunk now gets that chunk
   refused with `embedding_zero_norm`; the page keeps its text and every other
   vector. The failure names `gbrain embed <slug>`; see
   `docs/guides/write-refusals.md`.
