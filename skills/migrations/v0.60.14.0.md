## Lane B: connectors

One schema migration runs automatically:

- **v179** (handler) records a first sync attempt for every Google and GitHub
  source the previous autopilot freshness loop dispatched (a non-null
  `local_path` and not `syncEnabled=false`). Autopilot now dispatches a
  connector source only after a recorded attempt, so no source autopilot
  synced before the upgrade goes idle. Rerun-safe; it never rewrites an
  existing attempt.

Nothing else needs a command. Tell the user, and ask before running anything
that changes the brain:

1. **Held items.** A Google or GitHub item that fails three syncs in a row is
   held instead of wedging the source. Existing Gmail poison-ledger entries
   (`gmail_fail_counts`) are carried over once: a thread that failed three or
   more times becomes a held item with unknown sender, subject and date.
   Check with:

   ```bash
   gbrain sources status            # held items per source
   gbrain doctor                    # connector_held_items
   ```

   After the user agrees and the cause is fixed:

   ```bash
   gbrain sources retry-held <id> --dry-run
   gbrain sources retry-held <id>
   gbrain sync --source <id>
   gbrain sources status <id>       # a recovered item leaves the list
   ```

2. **A connector source that has never synced** now stays idle under
   autopilot and prints one notice. Run `gbrain sync --source <id>` once to
   enable it.

3. **`connector_fence_below_timeline`.** A managed connector sync may refuse a
   page whose facts or takes fence sits below its timeline. Preview
   `gbrain repair connector-fences --source <id>`, apply it after the user
   agrees with `--apply`, then `gbrain sources retry-held <id>`.

4. **`gbrain waiting`** may now say coverage is partial and name held Gmail
   threads. Present that answer as partial.

Mixed versions: upgrade the hosts that run the persistence consumer before
connector hosts, as in v0.60.11.0. An older consumer refuses a new
connector's page writes (`revision_conflict`) instead of losing data.
