## Lane E: links, capture, search, CLI and ingestion

No step here changes the brain without the user's agreement.

1. **Frontmatter links the stale sweep moved (#5749).** On brains with
   `link_resolution.global_basename=true`, the managed stale-link sweep could
   re-point a bare frontmatter wikilink (for example `related: [[topic]]`) at a
   transcript that repeats the term. This release moves the link extractor
   watermark, so every page re-extracts links once. Let the next sync or
   autopilot cycle run, or, with the user's agreement, run it now:

   ```bash
   gbrain extract --stale --catch-up --include-frontmatter
   ```

2. **Query instruction prefix (#5691, #3783).** Nothing changes unless the user
   sets it. If `gbrain doctor` reports `embedding_query_prefix`, show the user
   the command it prints and run it only if they agree. It affects query
   embeddings only; stored vectors are not re-embedded. Undo with
   `gbrain config unset embedding_query_prefix`.

3. **Private facts over HTTP (#5671).** If doctor's `memory_writeback` check
   warns that `facts.default_visibility` is private while agents read the brain
   over MCP or HTTP, ask the user whether those agents need to recall their own
   facts. If yes: `gbrain config set facts.default_visibility world`, then
   `gbrain bootstrap harness --yes` to refresh the installed instruction blocks
   (their private-posture text changed and shows as drifted until refreshed).

4. **Long sessions (#5701).** Claude Code and Codex sessions over 50 MiB are
   captured again from their recent tail. No action.

Verify: `gbrain doctor` shows no `embedding_query_prefix` warning (or the user
chose not to set one), and `gbrain get <page> --include-timeline-entries`
returns the page's timeline rows.
