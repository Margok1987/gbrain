# Upgrade to v0.59.16.0: managed write capacity, parked backups, coordinated stale extraction

This release adds schema v167 (a partial index for parked postcommit effects),
raises the default managed-write limits, and changes how repeatedly failing Git
and withdrawal targets are handled. It never deletes accepted write IDs or
receipts and does not start new background services.

1. **Upgrade and apply the schema.** Run `gbrain upgrade --no-autopilot-install`
   and confirm `gbrain --version` reports v0.59.16.0 or newer. If schema work did
   not complete, run `gbrain apply-migrations --yes --no-autopilot-install`.
   Upgrade every gbrain process that writes to the brain (serve, autopilot,
   hooks, global CLI) before relying on the new behavior.

2. **Run one full doctor.** Run `gbrain doctor --json` (not `--fast`) and relay
   any warning to the user:
   - `persistence_capacity`: a principal or the brain uses 80% or more of its
     permanent write IDs or receipt bytes. Run the `gbrain config set
     persistence.limits.<key> <value>` command the check prints, on the brain
     host. Raising a limit is a mitigation; IDs stay permanent.
   - `parked_effects`: a Git or withdrawal target failed five times in a row and
     was set aside. Inspect `gbrain sources writer status <source>`, fix the
     named cause, preview with the printed
     `gbrain sources writer retry-effects <source> --request-id <id> --dry-run`,
     then run it without `--dry-run` to authorize one more attempt.

3. **Receipt retention is now configurable.** The default stays 30 days. Only
   change it when the user asks: `gbrain config set persistence.receipt_retention_days <days>`.

4. **Managed stale extraction runs again.** On a managed brain,
   `gbrain extract --stale` now completes through the write coordinator. No
   manual action is needed; the `extract.stale` recommendation clears once
   extraction is current.

If a step fails, keep the doctor output and do not delete receipts, counters or
effect rows to make a warning disappear.
