# Upgrade to v0.59.12.0: keep database-only timeline history; hide unstamped derived pages remotely

Before this release, a coordinated page write (`put_page`, a managed sync of an
edited file, an import, a reconcile or a connector sync) deleted timeline
entries that existed only in the database, with no bullet in the page's
Markdown. Those were entries added before pages were written back to files and
entries produced by timeline extraction from the database. Takes stored in the
database but missing from the page's takes table were removed the same way.
This release keeps them. It cannot bring back entries that were already
deleted. There is no schema migration.

Remote readers now also treat extracted atoms and synthesized concept pages
that have no `visibility` field as private.

1. **Confirm a database backup exists before anything else writes to the
   brain.** Ask the user whether they have a recent backup of the database
   itself: `pg_dump` for Postgres, or a copy of the PGLite data directory made
   while gbrain was stopped. A Markdown export (`gbrain export`) does not
   include database-only timeline entries. If there is no backup, tell the user
   and recommend making one now. Do not make it for them without asking.

2. **Upgrade every process that writes to this brain.** An older gbrain process
   keeps deleting database-only timeline history every time it republishes a
   page. List the writers with the user: `gbrain serve`, autopilot and job
   supervisors, session hooks and any other machine or global CLI install that
   uses this database. Each must run `gbrain upgrade` and then be restarted.

   ```bash
   gbrain --version          # expect 0.59.12.0 on every writer
   gbrain autopilot --status --json
   gbrain jobs supervisor status --json
   ```

3. **Tell the user what was lost, plainly.** If pages were edited, synced,
   imported, reconciled or refreshed by a connector while an older writer ran,
   timeline entries that had no Markdown bullet may be gone. This release
   cannot restore them. Recovering them needs a database backup taken before
   the loss. Do not promise recovery without one.

4. **Remote readers of derived pages.** Atoms and synthesized concepts without
   a `visibility` field are hidden from remote MCP callers until a later
   release stamps explicit visibility on them. Local CLI reads are unaffected.
   Do not set `search.remote_private_pages` to restore remote access; that
   exposes every private page.

5. **A new write refusal.** A page write that adds a takes row whose number
   already belongs to a database-only take now fails with `take_row_collision`
   instead of overwriting that take. Renumber the new row, or add the existing
   take to the page's takes table with a `put_page` that passes the current
   `expected_revision`.

6. **Verify:**

   ```bash
   gbrain --version
   gbrain timeline <slug>    # an edited page still lists its older entries
   gbrain doctor
   ```
