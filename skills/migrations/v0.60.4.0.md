# v0.60.4.0: idle serve backoff, PGLite checkpoint guard, dream paid-loop breaker

The upgrade orchestrator applies migration 170, which only adds an index. If it
did not complete, run `gbrain apply-migrations --yes` on the brain host, then
`gbrain doctor`. Do not change the operator's search mode or engine.

Run one full `gbrain doctor --json` (not `--fast`) and relay the
`dream_paid_loop` row. If it warns, show the operator the looping dream keys
and the reset command it prints. Do not reset a key on your own: the operator
should first fix why those jobs die (a missing provider key, a failing
transcript, a quota), then run `gbrain dream reset-key '<key>'`. To list every
refused key, run `gbrain dream reset-key --list`.

Nothing else needs action. Idle `gbrain serve` processes now release their
extra Postgres connections by themselves, and large PGLite imports no longer
need to be split into batches to avoid freezing.
