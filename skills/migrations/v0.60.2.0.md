# Upgrade to v0.60.2.0: keep unchanged vectors through index rebuilds; re-seal pages remote search withholds

This release fixes two ways a brain's search index degraded silently. Index
rebuilds no longer throw away vectors on pages that use contextual retrieval
when nothing about the page changed. Pages chunked before the safe-chunk index
version (markdown and code) are no longer withheld from remote/MCP search
forever: re-importing unchanged content re-seals them, and a host-side repair
command drains the rest. Two additive schema migrations run automatically
(v168 adds a nullable column to `content_chunks`; v169 adds a small partial
index on `pages`).

1. **Upgrade every process that writes to this brain** (`gbrain serve`,
   autopilot and job supervisors, session hooks, every global CLI install).
   Each runs `gbrain upgrade` and is restarted.

   ```bash
   gbrain --version          # expect 0.60.2.0 on every writer
   ```

2. **Run one full doctor pass (not `--fast`) and relay the safe-chunk count.**

   ```bash
   gbrain doctor --json
   ```

   `contextual_retrieval_coverage` now counts pages of every kind below the
   safe-chunk index version (`details.unsealed_pages`, with
   `details.unsealed_code_pages` for code). Remote and MCP search withhold those
   pages' chunks. The count used to cover markdown only, so it may rise after
   upgrading even though nothing changed.

3. **Preview the re-seal, then apply it on the brain host.** It is a dry run
   unless `--apply` is passed. Show the user the preview first: it prints the
   pages affected and the estimated embedding cost. It takes no journal
   admissions, so it is safe on a managed brain and never hits a capacity limit.

   ```bash
   gbrain repair safe-chunks                   # preview
   gbrain repair safe-chunks --apply           # re-seal, then embed chunks that need it
   gbrain repair safe-chunks --apply --no-embed  # re-seal text only; embed later
   ```

   Add `--source <id>` or `--limit <n>` to work in batches; rerunning resumes.
   With `--no-embed`, run `gbrain embed --stale` later (ask the user first; it
   calls the embedding provider). `gbrain sync --full` also re-seals unchanged
   legacy pages and reports how many chunks need embedding.

4. **What changes for the user.** Remote search results now carry
   `safe_index_pending` whenever pages in the caller's scope are withheld, even
   when some results came back, so a partial answer is not mistaken for a
   complete one. The first rebuild of a contextual-retrieval page after this
   upgrade re-embeds it once (older vectors carry no record of what they were
   built from); after that, unchanged pages keep their vectors. `gbrain recall
   --grep` now finds matching facts older than the newest `--limit` rows.

5. **Verify:**

   ```bash
   gbrain repair safe-chunks --json    # 0 items
   gbrain doctor --json                # contextual_retrieval_coverage: unsealed_pages 0
   ```
